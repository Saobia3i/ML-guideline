Project Overview

What

A Visual Question Answering (VQA) system for brain MRI scans. Given an MRI image and a natural language question, the model returns a natural language answer — not just a class label.

🧠

Input

Brain MRI image + natural language question

💬

Output

Natural language answer explaining tumor presence and type

🎯

Goal

Thesis preparation — learn full ML pipeline on medical imaging domain

Why

Thesis topic is infant tumor detection. This project was built to:

  • Learn the complete ML pipeline hands-on before the real thesis dataset
  • Understand fine-tuning VLMs on medical images
  • Build a CNN baseline to compare against VLM (thesis requires comparison)
  • Learn deployment pipeline (Kaggle → HuggingFace → Gradio)
Key insight CNN says "glioma" — VLM says "Yes, this MRI shows a glioma tumor in the brain." The natural language explanation is the thesis novelty: interpretability in medical diagnosis.

All Phases — What, Why, How

Phase 0 · Day 1
Account & Environment Setup
Created accounts on Kaggle, HuggingFace, W&B, GitHub. Installed PyCharm, Python 3.14. Created vlm-env virtual environment. Installed core packages: torch, transformers, peft, accelerate, datasets, wandb, gradio.

Why: Isolated environment prevents package conflicts. Each project needs its own "bubble."
Phase 1 · Day 2-3
PyTorch Fundamentals
Learned tensors, autograd, and training loops. Verified PyTorch working locally. Connected W&B and logged first training run (linear regression: learned w=5.0 from scratch).

Why: Before fine-tuning a 2B model, must understand what backprop and gradient descent actually do. Confirmed with: gradient of x² at x=2 = 4.0 ✓
Phase 2 · Day 4
Dataset Preparation
Downloaded Brain Tumor MRI Dataset from Kaggle (7000 images, 4 classes: glioma, meningioma, notumor, pituitary). Converted to VQA format (image + question + answer JSON). Generated 5600 train + 1600 test samples.

Why: VLM needs image-text pairs, not just image-label pairs. Each image gets a natural language question and answer.
Phase 3 · Day 4
EDA (Exploratory Data Analysis)
Ran 01_eda.ipynb in PyCharm. Visualized class distribution (perfectly balanced: 1400 each). Visualized sample MRI images per class.

Why: Balanced dataset = no class imbalance problem. Confirmed data loaded correctly before training.
Phase 4 · Day 5-6
CNN Baseline (Kaggle)
Fine-tuned ResNet-50 (pretrained on ImageNet) on brain tumor dataset. Replaced final FC layer (2048→4). Trained 10 epochs on Kaggle T4 GPU. Logged to W&B.

Result: Train 99.6%, Val 95.25% accuracy.

Why: Thesis requires CNN vs VLM comparison. This is the baseline everything else is measured against.
Phase 5 · Day 7-12
QLoRA Fine-tuning (Kaggle)
Loaded Qwen2-VL-2B in 4-bit quantization. Applied LoRA adapters (r=8, trainable: 0.19% of params). Fixed dataset with proper label masking. Trained 5 epochs, 800 samples, ~65 minutes.

Result: Loss 17.1 → 5.847. Inference: 2/4 correct on sample test.
Phase 6
Deploy
Uploaded LoRA adapter weights to HuggingFace Hub. Built Gradio app with 2 tabs: VQA UI + Model Performance. Deployed to HuggingFace Spaces (free CPU).

Training Deep Dive

What is Transfer Learning

Instead of training from scratch (needs millions of images, weeks of compute), we take a model already trained on a large dataset and adapt it to our task.

ResNet-50 pretrained on ImageNet (1.2M images, 1000 classes)
        ↓
Freeze most layers (they already know edges, shapes, textures)
        ↓
Replace last layer: 1000 classes → 4 classes
        ↓
Fine-tune on 5600 tumor images
        ↓
Result: 95.25% accuracy in 10 epochs (~5 minutes)

What is QLoRA

Fine-tuning a 2B parameter model normally requires 16GB+ VRAM. QLoRA makes it possible on a 15GB T4 GPU. 

Step 1: Load model in 4-bit (Q = Quantization)
        2B params × 4 bits = ~1GB instead of ~4GB

Step 2: Freeze all original weights

Step 3: Add small LoRA adapter matrices (Lo = Low Rank)
        Only 4.3M params trainable (0.19% of 2.2B)

Step 4: Train only the adapters
        Gradients computed only for adapters → less memory

Step 5: Save only adapter weights (~50MB, not 4GB)

Label Masking — The Critical Fix

This was the most important optimization. Without it, loss was stuck at 9.3.

# WRONG — loss computed on question + answer
labels = input_ids.clone()   # all tokens included

# CORRECT — loss only on answer tokens
labels = input_ids.clone()
labels[:q_len] = -100        # -100 = ignore in loss computation

# Why: Model should learn to generate answers, not memorize questions
# With masking: loss 17.1 → 5.847
# Without masking: loss stuck at 9.3

Training Configuration (Final)

Parameter Value Why
epochs 5 Enough for convergence on 800 samples
batch_size 2 T4 VRAM limit
gradient_accumulation 4 Effective batch = 8
learning_rate 1e-4 Standard for LoRA fine-tuning
lr_scheduler cosine Smooth decay, avoids sharp drops
warmup_steps 50 Stable start before full lr
optimizer paged_adamw_8bit Memory-efficient AdamW
LoRA rank r 8 Balance between capacity and memory
max_length 384 Enough for question + answer
quantization nf4 4-bit Best quality/memory tradeoff

Issues Faced & Fixed

Bug scipy shadows torch — ImportError on first run
Error: attempted relative import beyond top-level package from scipy/_lib/array_api_compat/torch/__init__.py
Cause: scipy had a torch submodule that conflicted with actual PyTorch. Python 3.14 too new.
Fix: pip uninstall scipy -y then pip install scipy==1.13.1
Lesson: For ML projects, use Python 3.10 or 3.11 — not bleeding edge versions.
Bug Wrong PyCharm interpreter — running .venv instead of vlm-env
Cause: PyCharm auto-created .venv, but packages installed in manually created vlm-env.
Fix: File → Settings → Python Interpreter → point to vlm-env\Scripts\python.exe
Lesson: Always create environment through PyCharm, not manually. One project = one environment.
Bug prepare_dataset.py — "folder not found" warning
Cause: Script run from wrong working directory. Relative path data/Training resolved incorrectly.
Fix: cd E:\pycharm\PythonProject then run script from project root.
Lesson: Always run scripts from project root. Use os.getcwd() to verify.
Bug Kaggle GPU session cap reached
Cause: Kaggle allows only 1 active GPU session at a time. CNN notebook still running when VLM notebook started.
Fix: Stop CNN notebook session before starting VLM notebook.
Lesson: Always stop idle GPU sessions on Kaggle.
Bug Training loss stuck at 9.3 — model not learning
Cause: No label masking. Loss computed on entire sequence including question tokens. Model optimized for wrong objective.
Fix: Added label masking — set question token labels to -100 so loss only computed on answer tokens.
Result: Loss immediately dropped from 9.3 to 5.847.
Lesson: In VLM fine-tuning, label masking is mandatory — not optional.
Bug Training frozen at Epoch 2.07 — OOM during evaluation
Cause: eval_strategy="epoch" triggered evaluation on 200 test samples. Combined train + eval VRAM exceeded T4's 15GB.
Fix: Removed eval_strategy and eval_dataset from TrainingArguments.
Lesson: On T4 GPU, run evaluation separately after training, not during.
Bug NameError: model/train_ds not defined after session restart
Cause: Kaggle session restarted (timeout/refresh), all in-memory variables lost.
Fix: Re-run all cells from Cell 1 sequentially.
Lesson: Notebook state lives in memory — always save checkpoints. Never skip cells.
Bug pip install taking 20+ minutes on Kaggle
Cause: Installing all packages including pre-installed ones (transformers, wandb already in Kaggle image).
Fix: Only install missing packages: !pip install -q peft trl bitsandbytes qwen-vl-utils
Lesson: Kaggle pre-installs most ML packages. Only install what's missing.
Optimization prepare_model_for_kbit_training missing
Problem: Loading 4-bit model without preparing it for kbit training causes incorrect gradient flow.
Fix: Added model = prepare_model_for_kbit_training(model) before applying LoRA.
Why important: This enables gradient checkpointing and fixes layer norms for stable training.

Future Approaches — Best Practices

To improve this project's accuracy

  • More data — increase from 800 to 3000+ samples
  • Multiple QA per image — 4 questions × 1400 images = 5600 samples automatically
  • More distinctive answers — describe location, appearance, density (not just tumor type)
  • More epochs — 10-15 epochs instead of 5
  • Larger model — Qwen2-VL-7B on A100 GPU
  • LLaVA-Med — medical-specific VLM, better domain alignment

For your thesis (infant tumor detection)

  • DICOM preprocessing — use pydicom to convert raw scans → normalized PNG
  • Radiologist annotations — answers must come from medical expert, not just class labels
  • Sensitivity/Specificity metrics — more important than accuracy in medical AI
  • Grad-CAM visualization — show what the model "looks at" when predicting
  • Dataset augmentation — rotation, flip, brightness for medical images
  • Cross-validation — k-fold CV for small medical datasets

ML Engineering best practices learned

  • Always use label masking in VLM fine-tuning
  • Use prepare_model_for_kbit_training() before LoRA on quantized models
  • Don't run evaluation during training on T4 — OOM risk
  • Start with small dataset (800) to verify pipeline, then scale
  • Track everything with W&B — loss curve shows if training is healthy
  • Use Python 3.10/3.11 for ML — not bleeding edge versions
  • Save checkpoints frequently — Kaggle sessions timeout
  • CNN baseline first — gives reference point for VLM comparison

3. Baseline: ResNet-50 CNN (same as this project)
