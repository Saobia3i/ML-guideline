Machine Learning Engineering — Complete Guide

From first principles to thesis paper. Everything a 4th-year CSE student needs to know, explained the way a senior engineer would explain it — no fluff, no hand-holding.

// Section 01

What is Machine Learning?

"Machine Learning is programming a computer to learn from experience instead of programming it to follow explicit rules."

Traditional programming: you write if bright_spot and irregular_shape → tumor. You define every rule manually. It breaks when reality doesn't match your rules.

Machine learning: you give the computer 10,000 MRI images labeled "tumor" or "not tumor." The computer figures out the rules itself. It discovers patterns you never thought to write.

The Core Idea — Pattern → Generalization

# What ML actually does:

Data         → [image1: glioma, image2: notumor, image3: glioma ...]
Training     → model adjusts 25M internal numbers (weights)
               until it correctly predicts the training data
Generalization → model applies learned pattern to NEW images
               it has never seen before

# The "learning" = adjusting weights via gradient descent
# The "pattern" = statistical regularities in pixel values

Three Types of ML

Type What Example You Provide
Supervised Learn from labeled examples Tumor classification image + label
Unsupervised Find hidden structure in data Patient clustering image only
Reinforcement Learn via reward/punishment Game playing, robotics reward signal
Your thesis context Infant tumor detection = supervised learning. You have MRI images + radiologist labels (tumor/no tumor, tumor type). Model learns to replicate radiologist judgment.

What "Training" Actually Means

Training = running an optimization algorithm (gradient descent) that minimizes a loss function. The loss measures "how wrong is the model." Training pushes loss toward zero.

# The training loop — this is ALL of machine learning:

for each batch of data:
    forward pass   → model makes prediction
    compute loss   → measure how wrong the prediction is
    backward pass  → compute gradient (which direction to adjust weights)
    update weights → take small step in gradient direction

# Repeat 10,000 times → model gets better
# This is gradient descent. This is ALL of ML training.

What is a Vision Language Model?

A VLM is a model that understands both images and text simultaneously. It can look at an MRI and answer questions about it in natural language.

Definition

VLM = Vision Encoder + Projection Layer + Language Model. The vision encoder converts images to vectors. The projection layer aligns image vectors with text vectors. The language model reasons over both to generate text.

VLM Architecture — Internal Structure

Input: [MRI image] + "Does this show a tumor?"

Step 1: Vision Encoder (ViT)
  Image → 14×14 patches → each patch tokenized
  Output: 256 visual tokens (vectors)

Step 2: Projection Layer (MLP)
  Visual tokens → projected to LLM's embedding space
  This is the "bridge" between vision and language

Step 3: LLM Backbone (Qwen2)
  [visual tokens] + [text tokens] → transformer attention
  Model attends to both image content and question

Step 4: Generation
  Autoregressively generates: "Yes, this MRI shows..."
  Token by token, conditioned on image + question

Why VLM over CNN for medical imaging thesis

Capability CNN VLM
Classification ✅ Excellent ✅ Good
Explanation ❌ Just a label ✅ Natural language
Multi-task ❌ One task per model ✅ Any question
Clinical utility ⚠️ Limited ✅ Doctor-friendly
Fine-tuning complexity Simple Complex (QLoRA needed)
Thesis novelty Low (done everywhere) High (newer, impactful)

VLM Fine-tuning vs Training from Scratch

# Training from scratch — NOT what you do:
Random weights → train on 100M image-text pairs → months → $1M+

# Fine-tuning — what you do:
Pretrained Qwen2-VL (already knows vision + language)
  ↓
Add LoRA adapters (tiny extra weights, ~0.19% of model)
  ↓
Train only adapters on your 800 medical samples
  ↓
Model adapts to your domain in ~1 hour
Key insight for thesis Fine-tuning is the industry standard. Google, Meta, every company fine-tunes pretrained models. Nobody trains VLMs from scratch except the 5 labs that have the compute budget. Your thesis contribution is the fine-tuning methodology + domain adaptation + evaluation, not building the architecture.

How Machine Learning Actually Works

The Mathematics (simplified)

# A neural network is just:
output = activation(weights × input + bias)

# Training = finding the right weights
# Loss function = measures wrongness
loss = mean((predictions - true_labels)²)   # MSE
loss = -sum(true × log(predicted))          # CrossEntropy (classification)

# Gradient descent = walking downhill on loss landscape
weight = weight - learning_rate × gradient_of_loss

# Backpropagation = chain rule to compute gradients
# This is what loss.backward() does in PyTorch

Key Concepts Every ML Engineer Must Know

Overfitting vs Underfitting

Underfitting: model too simple → high train loss, high val loss
              Fix: bigger model, more features, more epochs

Overfitting:  model memorized training data → low train loss, HIGH val loss
              Fix: more data, dropout, regularization, early stopping

Sweet spot:   low train loss AND low val loss → generalization

Train / Validation / Test Split

Train set (70-80%): model learns from this
Val set   (10-15%): tune hyperparameters, monitor overfitting
Test set  (10-15%): NEVER touch until final evaluation
                    final reported accuracy comes from here

# Common mistake: tuning on test set → inflated results → paper rejected

Learning Rate — The Most Critical Hyperparameter

Too high: loss oscillates or explodes — never converges
Too low:  loss decreases but very slowly — wastes compute
Just right: loss curves smoothly downward

# General rules:
Full fine-tuning:  1e-5 to 1e-4
LoRA fine-tuning:  1e-4 to 3e-4
CNN last layer:    1e-3 to 1e-4
Training from scratch: 1e-3 with warmup

Batch Size and Gradient Accumulation

# Batch size = how many samples per weight update
Large batch: stable gradients, needs more VRAM
Small batch: noisy gradients, but can fit in limited VRAM

# Gradient accumulation = simulate large batch with small VRAM
batch_size=2, gradient_accumulation=8
→ effective batch = 16 (update every 8 steps)
→ same math, less VRAM

Metrics — What to Measure

Metric Formula When critical
Accuracy correct / total Balanced datasets
Precision TP / (TP+FP) When false positives are costly
Recall (Sensitivity) TP / (TP+FN) Medical: missing tumor = catastrophic
Specificity TN / (TN+FP) Medical: false alarm rate
F1 Score 2×(P×R)/(P+R) Imbalanced datasets
AUC-ROC area under ROC curve Medical AI papers, gold standard
Thesis critical In medical AI, Recall/Sensitivity is more important than Accuracy. Missing a tumor (False Negative) is far worse than a false alarm (False Positive). Always report both. Papers that only report accuracy get rejected.

How VLM Learning Works

The Transformer — Foundation of Everything Modern

# Attention mechanism (core of transformer):
"Which parts of the input should I focus on?"

For text: "The tumor [in the frontal lobe] appears malignant"
          ↑ model attends to [in the frontal lobe] when processing "malignant"

For vision: each image patch attends to related patches
            patch of tumor mass attends to surrounding tissue

For VLM: text tokens attend to image patches and other text
          "where is it?" → model attends to spatial image regions

LoRA — Why It Works

# Full fine-tuning:
All 2B weights updated → 2B gradients stored → 16GB VRAM → expensive

# LoRA insight: weight updates are low-rank
ΔW = A × B  (where A is n×r, B is r×n, r << n)
r=8, n=4096 → A is 4096×8, B is 8×4096
Parameters: 4096×8 + 8×4096 = 65,536 (vs 4096×4096 = 16M)
VRAM saving: ~250× fewer parameters to train

# QLoRA adds quantization on top:
Base model in 4-bit (frozen) → ~1GB
LoRA adapters in fp16 (trainable) → ~50MB
Total VRAM: ~4GB vs 16GB for full fine-tuning

Vision Encoder Deep Dive (ViT)

Input image: 336×336 pixels
↓
Split into 14×14 patches (each 24×24 pixels)
↓
Each patch → linear embedding (flatten + project to 768-dim vector)
↓
Add position embedding (tells model WHERE each patch is)
↓
Stack of transformer layers → patches attend to each other
↓
Output: 576 visual tokens, each 768-dim
These are the "image features" fed to the LLM

Why Label Masking is Critical in VLM Fine-tuning

# Input sequence to model:
[IMG_TOKEN × 576] [QUESTION_TOKENS] [ANSWER_TOKENS]

# Without masking (WRONG):
Loss computed on ALL tokens including question
Model learns to predict question tokens too
Result: model memorizes question format, not answer content
Symptom: loss stuck at high value (9.3 in your case)

# With masking (CORRECT):
Question labels → -100 (PyTorch ignores these in loss)
Loss computed ONLY on answer tokens
Model learns to generate correct answers
Symptom: loss drops properly (17 → 5.8 in your case)

Complete ML Training Pipeline

Every ML project, from tumor detection to self-driving cars, follows this pipeline. Know this cold. 

1. Problem Definition
   What are inputs? What are outputs? What metric matters?
   Medical: inputs=MRI, output=diagnosis, metric=sensitivity

2. Data Collection & Annotation
   Raw data → labeled dataset
   Medical: DICOM files + radiologist annotations

3. Data Preprocessing
   DICOM → PNG → normalize → resize → augment
   Split: 70% train / 15% val / 15% test

4. Exploratory Data Analysis (EDA)
   Class balance? Image quality? Outliers?
   If imbalanced: use weighted loss or oversampling

5. Baseline Model
   Simplest model that works (ResNet-50, logistic regression)
   Sets the bar everything else must beat

6. Model Selection & Architecture
   Based on data type, size, compute budget
   Image: CNN or ViT | Text: Transformer | Both: VLM

7. Training
   Set hyperparameters → train → monitor loss curves
   Watch for: divergence, plateau, overfitting

8. Evaluation
   Run on TEST set (never val set)
   Report: accuracy, sensitivity, specificity, AUC-ROC

9. Error Analysis
   Which samples did model get wrong? Why?
   Grad-CAM: what is model looking at?

10. Iteration
    More data? Better augmentation? Different architecture?
    Repeat steps 3-9 until satisfied

11. Deployment
    Quantize → serve via API → monitor in production

Standard Paper Structure

Abstract (200 words)
  Problem + Method + Key result + Significance
  Write this LAST

1. Introduction
  - Clinical problem (infant tumor diagnosis is hard/slow/expensive)
  - Gap (existing methods lack explainability)
  - Your contribution (VLM fine-tuned with QLoRA + clinical language)
  - Paper organization

2. Related Work
  - CNN-based tumor detection (cite 5-10 papers)
  - VLMs in medical imaging (LLaVA-Med, BiomedGPT)
  - Fine-tuning methods (LoRA, QLoRA papers)
  - What gap your work fills

  - Dataset description (your infant dataset + augmentation)
  - Model architecture (Qwen2-VL / LLaVA-Med + LoRA config)
  - Training setup (hyperparameters, hardware, epochs)
  - Evaluation protocol (train/val/test split, metrics)

4. Experiments & Results
  - Quantitative: accuracy, sensitivity, specificity, AUC-ROC
  - Qualitative: example predictions with Grad-CAM
  - Ablation study: with vs without fine-tuning, different r values
  - Comparison: CNN baseline vs VLM

  - Why VLM outperforms/differs from CNN
  - Clinical implications
  - Limitations (small dataset, single institution)

6. Conclusion
  - Summary of contributions
  - Future work

  - Use Zotero or Mendeley to manage citations

Ablation Study — What it is and why you need one

Ablation Study

Remove one component at a time to prove each component contributes. Example: "VLM without fine-tuning: 50% accuracy. With fine-tuning: 78%. Fine-tuning contributes +28%." This proves your methodology choices are justified, not arbitrary.

Common Mistakes — Senior Engineer Perspective

Mistake 1: Reporting accuracy on imbalanced data If 90% of samples are "no tumor", a model that always predicts "no tumor" gets 90% accuracy. Always report sensitivity + specificity + AUC-ROC for medical datasets.
Mistake 2: Touching test set during development Use val set for tuning. Test set is sacred — only evaluate once at the end. Repeated evaluation on test set = data leakage = inflated results = paper rejected.
Mistake 3: No ablation study "Our model achieves 92%" means nothing without: what does it achieve without fine-tuning? Without augmentation? Without your specific architecture choice? Ablations prove your contribution.
Mistake 4: Missing label masking in VLM fine-tuning This is the most common VLM fine-tuning bug. Loss gets stuck because model learns to predict questions too. Always mask question tokens to -100.
Mistake 5: Using latest Python for ML Python 3.14 caused scipy/torch conflicts. Always use Python 3.10 or 3.11 for ML projects. Stability > newest features.
Mistake 6: Training on full dataset before verifying pipeline Test with 100 samples first. Verify loss decreases. Verify inference works. Then scale to full dataset. Saves hours of wasted GPU time.
Mistake 7: Not saving checkpoints Kaggle sessions timeout. Colab disconnects. Always save_pretrained every epoch. Never run a multi-hour job without checkpointing.
Best practice: Reproducibility Set random seeds everywhere. Log all hyperparameters. Save training config alongside model. Another person running your code should get the same results. Papers without reproducibility details get rejected. 
# Reproducibility setup — put at top of every training script:
import torch, numpy, random

SEED = 42
random.seed(SEED)
numpy.random.seed(SEED)
torch.manual_seed(SEED)
torch.cuda.manual_seed_all(SEED)
torch.backends.cudnn.deterministic = True
